# Apple-1-inspired computer: implementation evidence

Recorded 2026-10-01. This report describes the new gate-built 6502 computer;
earlier M0 reports describe historical fixtures. The delivered computer is a
development candidate. Desktop interaction and fresh-user acceptance remain open.

## What executes

`circuits/bitwright.circ` joins a native gate CPU, a gate-built memory decoder,
4 KiB RAM, a 4 KiB firmware window and the circuit terminal. CPU storage uses
cross-coupled gates and master/slave cells. The expanded CPU contains 7,200
one-bit Boolean gate equivalents, represented by 5,013 gate components; repeated
selection masks use explicitly documented bitwise gate symbols. The CPU contains
no built-in memory, arithmetic, selector, register, counter or processor component.

The console uses single-bit DFFs, bulk character RAM and original glyph ROM.
Its gates own keyboard latching, cursor, wrap/scroll and character-to-pixel
generation. Java only queues ASCII and retains circuit-supplied pixel words.
The file feeder never parses opcodes/addresses or writes machine RAM. Original
Bitwright firmware, executing on the circuit CPU, performs every load deposit.

All 151 documented NMOS 6502 encodings are implemented. This is functional
instruction behavior, not original bus-cycle/electrical fidelity. No dummy bus
writes, undocumented opcodes, full 6820 PIA, analog composite video, cassette,
filesystem or MHz throughput is claimed. Reset intentionally establishes
A/X/Y=0, SP=FD and P=24 before vector fetch. IRQ/NMI are logical active-high
inputs and are tied inactive in the complete computer. See the CPU manifest.

## Native execution evidence

- Independent differential execution: 362 cases, 1,900 instruction retirements,
  all 151 documented encodings, register/flag/PC/SP state and ordered writes.
  Finite coverage is not an exhaustive correctness proof.
- CPU smoke: 27 CPU checks, 49 gate-DFF capture/hold/reset checks, eight full-adder
  truth rows and eight register-bank enable/reset checks; native save/reopen also
  passes. High-clock enable changes must not cause a spurious capture.
- Terminal smoke: 119 native assertions covering input acknowledgement, busy
  writes, actual character RAM/glyph pixels, wrap, scroll, clear and reset.
- Host adapter: 11 checks for queue stability/acknowledgement, cloning, reset,
  overflow, ASCII files, newline normalization and raw pixel storage.
- Full computer: 205 assertions passed in the reference-host run. Firmware loaded
  and ran `hello` (70 bytes) and `sum` (116 bytes) through the actual host ASCII
  boundary. Every loaded RAM byte matched the assembled image. `K` was echoed;
  input `9` produced `SUM (HEX) = 2D` and RAM 0080 contained 45. Both programs
  returned to the monitor. A fresh warm-reset banner appeared and program RAM
  survived. Display writes were checked against native Busy and no CPU fault
  or oscillation occurred.

The final harness additionally checks exact K/9 glyph pixels after the eight-row
render interval. The reference-host timing run predates those extra pixel
assertions; the interval was independently established by the terminal tests.
These timings exclude host desktop keyboard dispatch and GUI repaint scheduling.

## Software and reproducibility checks

The Python suite has 46 tests, including exhaustive reference-model binary
ADC/SBC flags (262,144 combinations), 40,000 valid-BCD combinations, assembler
diagnostics, monitor workspace protection and decimal-mode recovery. These
software-only arithmetic counts are not native exhaustive ALU coverage.

Twenty-five software artifacts regenerate deterministically. Native generation
is checked before CI builds, and CI rejects tracked build differences. Legacy
combinational/sequential vectors, intentional failures, missing-output/setup
errors, positive/negative RAM signatures and watchdogs still run. The wrapper
rejects incorrect vectors even when the simulator exits with status zero.

The main computer saves/reopens through Logisim and boots its firmware again.
The package checks ZIP checksums, native dependencies, relocated RAM/text fixtures
and actual firmware boot. Relocated harness classes and the host JAR come from
the extracted package. An explicit missing-JAR regression prevents fallback to
the checkout. Offline tests use process-local network denial with a negative
control; they do not change host networking. Desktop offline use is a separate
unverified acceptance item.

## Measured performance

Reference host: Apple M4, 24 GiB RAM, macOS 26.3.1 (a), arm64; Temurin
21.0.12.1+1, Python 3.12.12 and checksum-pinned Logisim-evolution 5.0.0.
No other project simulator workload ran during the final integrated measurement.
Results are single-run measurements, not latency percentiles or guarantees.

| Measurement | Native result |
| --- | --- |
| Two-program integration | 140,943 cycles; 6,005 writes; 314.035 s; 448.8 cycles/s |
| Hello file to program's input prompt | 52,048 cycles; 120.035 s |
| Sum file to program's input prompt | 82,970 cycles; 180.715 s |
| K capture to display write plus eight pixel-row cycles | 90 cycles; 223.836 ms |
| 9 capture to display write plus eight pixel-row cycles | 106 cycles; 239.596 ms |
| Bounded boot/idle benchmark | 3,000 cycles; 632 completed instructions; 6.441 s |
| Boot/idle throughput | 465.8 cycles/s; 98.1 instructions/s |

The short benchmark counts fetch boundaries minus initial entry; IRQ/NMI are
inactive. Its instruction mix differs from loading and is not a universal CPU
rating. Background screen refresh requires 7,680 cycles, so scrolling can remain
visually incomplete much longer than an individual newly printed glyph.

Gate-only register-bank clock enables, direct cell wiring and bitwise selection
masks reduced an isolated, sequentially measured differential run from 25.569 s
to 15.339 s (about 1.67× throughput); CPU time fell from 27.419 s to 17.524 s.
The optimized circuit passed the identical 362 cases/1,900 retirements. Monitor
changes reduced reference instruction counts for file loading by about 25%.
These are separate experiments, not an assumed multiplicative full-system gain.

The older roughly 150 cycles/s observation occurred while other CPU experiments
were running. It is not a controlled baseline and must not be used as a speedup
claim. Gate simulation remains the dominant practical limitation: loading small
programs takes minutes. The old proposed 250 ms desktop-response target is not
established by two native samples that exclude GUI scheduling.

## Reproduce and inspect

Run `python3 tools/bw.py build`, `test`, `package`, and `offline-test` with the
pinned JDK/simulator. Linux vector execution uses `xvfb-run -a` for `test`.
`test-machine` runs the complete file-loading/program path alone with a 20-minute
timeout and cycle watchdogs. Raw outputs are written under `build/test-results`;
native painter renders under `build/renders` are circuit previews, not screenshots.
`python3 tools/bw.py benchmark` reproduces the bounded boot/idle instruction-rate
measurement; run it without another project simulator workload competing for CPU.

Enter the running `Apple1Console` instance from the main circuit's context menu.
Opening its library definition instead shows independent simulation state.
Reset starts asserted; release it and enable ticks. Wait for the backslash prompt
before selecting a .mon file. Files include a run command. Monitor commands fold
lowercase; program GETC returns raw ASCII. Backspace edits the input buffer but
does not erase the old glyph or cross wrapped rows; Escape cancels a command.

## Remaining acceptance

Desktop automation repeatedly timed out attaching to the installed Logisim app,
including after the CPU experiments finished. No successful visible file-picker,
fresh keyboard/refocus or offline desktop run of this final computer is claimed.
Native execution and pixel tests do not replace that evidence. Keep the PR draft
and release acceptance open until the visible flow and supported platforms are
checked. The implementation is available for review and use with these limits.
