# 2026-10-01 — Begin the feasibility bench

## Question

Can native inspectable circuits, reliable automated failure detection, and real
mouse/display interaction coexist in a small offline Logisim-evolution project?

## Decisions

The approved v1 target uses an 8-bit datapath and 16-bit addresses. Single-bit
flip-flops and bulk RAM/ROM are allowed; arithmetic, selection, registers,
counters, and instruction control are built from gates. Host adapters are separate
from CPU-visible device logic. A source-available Java canvas may retain pixels
and capture input. The first implementation gate is M0, not the CPU.

## Work initiated

The architecture, opcode contract, roadmap, source-ownership policy, and scoped
backlog are recorded alongside the M0 implementation. The simulator target is
Logisim-evolution 5.0.0; the bench deliberately has no CPU or assembler. Native
fixtures, bridge source, test tooling, and packaging are implemented as an M0
candidate; that does not close the desktop acceptance gate.

## Evidence and open questions

Use the [M0 evidence report](../evidence/m0-2026-10-01.md) for actual command output, measured behavior, and
acceptance status. The packaged simulator returned zero for an intentionally
incorrect vector, confirming why the wrapper must validate printed pass/fail
counts. Both fixture sources passed four gate vectors and fifteen stateful storage
rows. The bridge passed 367 contract checks; callback tests cover all button bits
and arrival immediately before acknowledgement.

Native command-line round trips, relocated loader checks, and native renders are
recorded separately from GUI acceptance. Initial desktop automation attachments
timed out. Later in the same session, attachment succeeded and the agent operated
the extracted candidate in Logisim-evolution 5.0.0 with the user watching.

The stock Keyboard visibly sent `HELLO BITWRIGHT` to TTY. A canvas click with Ack=0
exposed X=60, Y=60, Buttons=`001`, and Valid=1; another click increased the queued
events without changing that front packet. Using the visible clock toolbar while
paused, one full cycle acknowledged the press and exposed the release at the
same coordinates, and the next cycle drained it. A stock red center pixel appeared
after a cycle. Clear removed the stock pixel immediately and cleared the custom
canvas on its next falling-edge cycle. With ticks resumed, twenty clicks painted
a dotted `B`; queue and overflow both ended at zero.

Attempted automated drags produced sparse dots and unexpected control toggling;
the cause is unverified, so continuous drag routing is not a passing result.
Returning to the stock Keyboard after drawing also left an unresolved observation:
attempts to enter `KEYBOARD + PIXELS OK`, `READY`, and individual `r/e/a/d/y` keys
plus Return produced no further visible TTY text, and the Keyboard buffer appeared
empty. This does not identify whether the application or automation/input routing
was responsible; initial `HELLO BITWRIGHT` entry remains a confirmed success.
Keyboard refocusing, drag, release outside the canvas, focus loss while held,
live overflow/recovery, network-disabled operation, fresh GUI save/reopen, and
input latency remain open.
The [evidence report](../evidence/m0-2026-10-01.md) records the exact settings and
remaining checks. M0 remains open, and CPU work has not started.

Reading only the host poker adapter initially suggested that its synthesized first
press loses the button ID. Inspection of the full Poke tool path found that the
original event follows it. The bridge must ignore the synthetic callback and
process the real event. Callback tests cover this path, and the later live check
confirms primary-button click packets; continuous gestures and other button
routing still need evidence. This is why the caller and adapter both matter when
reasoning about host integration.

Review also caught a queue race: a first event arriving just before an ACK edge
could be consumed before the circuit had seen it. Acknowledgement now requires
previously exposed VALID, and regression tests cover the race and reset priority.
