# Native M0 circuits

Open `bitwright.circ` in **Logisim-evolution 5.0.0**, after building or unpacking `../build/bitwright-bridge.jar`. The project uses that relative JAR path and the relative `manual/foundations.circ` native library. The libraries are inspectable in the left project tree.

## Ownership

- `manual/foundations.circ` is manually maintained native source. Edit/save it with Logisim; generation never changes it.
- `generated/*.circ` and `bitwright.circ` are generated by `tools/generate_circuits.py`. Edit that Python source, regenerate, and commit both. `--check` compares without writing.
- The manual and generated foundations are equivalent implementations with independent file ownership; both must pass the same vectors. The manual file may be rearranged without changing the generator.
- Files pin classic component appearance and explicit ports, rather than depending on application display preferences.

## Workbench operation

Use the **Poke tool** (hand), reset simulation, and enable ticks. Start at a modest clock rate such as 16 Hz.

1. **Text:** click the Keyboard component and type ASCII. Its 32-character host queue drives the TTY directly, with data/available sampled on rising clock edges. This demonstrates the host adapter; the future machine-side FIFO is not present.
2. **Stock pixels:** edit the X/Y (7-bit), Color (3-bit), and Plot inputs. With Plot=1, each falling host-clock edge draws at that coordinate. Color bits are red/green/blue from high to low. Clear resets the image.
3. **Mouse pixels:** choose a nonzero Color, set Plot=1 and Ack=1, enable ticks, then press and drag within the custom canvas. Ordinary gates permit plotting only while a valid packet has primary-button bit 0 set. MouseX/Y feed its pixel-command bus. The bridge never paints just because a mouse event arrived.
4. **Packet retention:** set Ack=0, click/drag, and inspect MouseValid, MouseX/Y, MouseButtons. The front packet remains stable until Ack=1 and a falling edge consumes it. MouseOverflow reports host-queue overflow; OverflowClear clears that diagnostic.
5. **Reset:** set Reset=1 then 0. Reset has priority, empties the host queues and clears both display images. Hold Clear=1 to clear without resetting inputs.

The custom canvas queue is a host adapter queue, not the planned 16-event circuit FIFO. All three button bits are reported; only primary-button events enable this demo's paint gate. No hover events are promised. This is an I/O feasibility demonstrator, not yet a computer.

## Foundation and RAM checks

`GateAnd` is a complete two-input gate truth table fixture. `LoadBit` builds feedback selection from NOT/AND/OR and stores one bit in a permitted D flip-flop. Data is captured only on a rising Clock pin with Load=1; asynchronous Reset wins.

`generated/ram-harness.circ` loads bank **M0_RAM**. The first RAM byte is split into bits and compared to **A5** with gates. Two D flip-flops shift a constant 1 so the `halt` output asserts after two rising edges. TTY output contains `pass` and `signature` in native pin order (top to bottom, then left to right); the runner derives this order from the native file. `halt` is consumed by Logisim. A wrong byte must yield pass=0, even though Logisim itself exits zero.

`generated/never-halt.circ` deliberately never halts. It exists only to verify the external test timeout. Do not run it unbounded.

Do not trust Logisim vector process exit status: in the pinned release, an intentionally failing vector still exits zero. The repository runner validates the printed result counts.
