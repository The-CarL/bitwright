# Native M0 keyboard terminal

Open `bitwright.circ` in **Logisim-evolution 5.0.0**. Keep the relative `manual/foundations.circ` library beside it. The default bench uses only native simulator components; it needs no custom Java library, mouse component, or pixel display.

## Run and inspect

Choose the **Poke tool**, enable clock ticks, then click inside **Keyboard** and type ASCII. The stock Keyboard's 32-character host queue feeds the stock 32-column, 8-row TTY. The `TerminalControl` subcircuit implements the transfer and clear controls using gates; open it in the circuit tree to inspect its logic.

| Control | Default | Behavior |
| --- | --- | --- |
| `Run` | 1 | Forward one character per rising clock edge when input is available. At 0, stop forwarding and retain queued input. |
| `Clear` | 0 | At 1, clear the text screen and inhibit forwarding. The input queue is retained; return to 0 to resume. |
| `Reset` | 0 | At 1, clear both the keyboard queue and the text screen, with priority over Run. Return to 0 afterward. |

The native circuit pins its `simulationFrequency` to **64 ticks/second**. With one high tick and one low tick per clock cycle, this provides up to **32 character transfers/second**. The native simulator may run more slowly under load. This setting is a starting point, not a measured latency claim. The controls do not gate the clock. Pausing simulator ticks retains queued input; resuming ticks resumes transfers when Run=1 and both clear controls are 0.

Click Keyboard again after operating a control or changing focus to another application. Native tests verify circuit transfer behavior; actual desktop focus/refocus, save/reopen, and offline acceptance are recorded separately in the evidence report. A circuit cannot force the operating system to deliver keyboard focus.

| Observable pin | Meaning |
| --- | --- |
| `Available` | A character is waiting at the front of the host queue. |
| `ASCII[7]` | Front character; observing it does not dequeue it. |
| `Transfer` | Run AND Available AND NOT(Clear OR Reset); enables both dequeue and TTY write. |
| `TtyClear` | Clear OR Reset. |
| `KeyboardClear` | Reset. The short internal tunnel name `KClear` carries the same signal. |
| `ClockSeen` | The ungated native clock. |

M0 demonstrates host character transfer. The future CPU and circuit-owned keyboard FIFO are not present. The stock host queue is finite, so input beyond its capacity may be lost; it does not export an overflow flag.

## Source ownership and generation

- `manual/foundations.circ` is manually maintained native source, saved through Logisim. Edit/save it directly; generation never writes it.
- `bitwright.circ` and `generated/*.circ` are generated by `tools/generate_circuits.py`. Edit the Python source, regenerate, and commit both. Use Python 3.12+; `--check` compares without writing.
- The native and generated foundation fixtures have independent file ownership and run the same vectors. The manual layout can change independently.
- The default generator does not read, load, or check the optional mouse experiment. `--experiment` additionally generates or checks `../experiments/mouse-canvas/workbench.circ`.
- Components have explicit ports and appearance attributes. The control subcircuit's custom native appearance keeps its interface readable and deterministic.

## Fixtures and meaningful checks

`GateAnd` has a complete two-input truth table. `LoadBit` builds feedback selection from NOT/AND/OR gates around one permitted D flip-flop; sequential vectors test rising-edge capture, load/hold, and asynchronous reset priority.

`TerminalControl` has all 16 combinations of Run, Clear, Reset, and Available in `tests/vectors/terminal-control.txt`. `workbench-reset.txt` verifies the real front panel's eight control combinations. The separate native text smoke test exercises the native Keyboard queue and TTY screen contents, queue retention, clear/reset, and resumed transfer rather than only checking the control equations. It injects characters into the native queue; it does not generate desktop keyboard events.

`generated/ram-harness.circ` loads bank **M0_RAM**. Gates compare its first byte with **A5**. Two D flip-flops shift a constant 1 so `halt` asserts after two rising edges. TTY table output contains `pass` and `signature` in native pin order; the repository runner derives that order from the native file. A wrong image must yield pass=0 even though Logisim exits zero.

`generated/never-halt.circ` deliberately never halts, to prove the external timeout works. Do not run it unbounded. The pinned Logisim release also exits zero for deliberately failing test vectors; the repository runner validates its printed pass/fail counts.

The earlier mouse/pixel workbench is preserved at `experiments/mouse-canvas/` in
a full source checkout. It is outside v1 and excluded from the primary ZIP.
