# M0 feasibility evidence — 2026-10-01

**Status: candidate implemented; desktop acceptance remains open.** No CPU,
assembler, boot monitor, or circuit-owned input FIFO is implemented yet. The
approved M0 gate requires actual desktop mouse/display evidence before CPU work.

## Reproduction environment

- macOS 26.3.1 (a), build 25D771280a.
- Python 3.12.12 and Temurin JDK 21.0.12.1+1.
- Official Logisim-evolution 5.0.0 standalone JAR; SHA-256
  `6b368e894742c04cc83aa9830f869bcab0190ede4df43ad6fecdb89b3a23a41c`.
- Commands: `python3 tools/bw.py test` and `python3 tools/bw.py package`, with
  `JAVA_HOME` and `LOGISIM_JAR` selecting those exact local tools. On Linux, run
  the test command under `xvfb-run -a`; vector execution initializes Swing.
- Test output is captured locally in `build/test-results/`. CI retains those
  logs as an artifact. This report deliberately distinguishes command-line
  simulator evidence from desktop interaction.

The Python runner has ten passing unit tests for its validation and failure
boundaries. The circuit vectors run against the real pinned simulator, not a
Python reimplementation. The stock pixel test uses a version-specific native
image inspection adapter; it is development tooling only.

The native renders are in `build/renders/`. They are artifact renders, not
desktop screenshots. Layout inspection found a stock-video reset wire crossing
an X input connection; that collision was fixed and the pixel-path test added to
prevent a similar fault from passing a reset-only test.

## Bridge behavior and boundary

The Java contract suite passes **367 checks** covering pixel commands, coordinate/color handling,
reset/clear, queue capacity/overflow, packet stability, acknowledgements,
cloning, and mouse press/drag/release callbacks for all three buttons. The host
queue contains at most 256 packets; overflow drops new packets and is sticky.
The planned machine-side 16-event FIFO is absent from M0.

The custom canvas never paints because a host event arrived. Native gates route
mouse coordinates to the pixel bus and permit plotting only for a valid packet
with the primary button held. The bridge applies that command on a falling
clock edge. Its source and tests ship in the candidate package.

Inspection of the complete native Poke tool path showed that its synthesized
first callback is followed by the original host event. The bridge ignores the
synthetic no-button callback; it does not invent a primary button. Real desktop
routing remains a separate acceptance item.

Review found that an arriving first event could otherwise be consumed on the
same falling edge before VALID had been exposed. ACK now requires previously
exposed VALID; regression cases cover that arrival race, an appended release,
and reset priority. The resulting JAR SHA-256 is
`fdc5373d9ab45340ad294e8a8f7f0f0e386cc0c874d54cd8adb0a4be1496e08f`.

## Performance limits of this evidence

On this machine, individual foundation-vector processes took approximately
0.7–1.3 seconds including JVM startup; RAM signature runs took approximately
0.6–0.8 seconds including startup. These tiny tests are **not** measurements of
computer cycles/second, instructions/second, or input latency. The terminal test
uses a three-second deadline only to stop an intentionally interactive process.

The proposed input-to-visible-response target of 250 ms has not been measured.
No full-computer performance or animation-rate claim is supported yet.

## Desktop acceptance still required

Automation discovered the running Logisim application but could not attach to
it by application name, bundle ID, or path; attachment attempts timed out.
No screenshot, click, key entry, drag, or desktop focus result is claimed.

Use the candidate ZIP for these checks and record platform, simulator version,
outcome, and evidence before closing M0:

1. Extract into a fresh folder, disconnect networking, open
   `circuits/bitwright.circ` in the pinned desktop application, reset, and enable
   ticks. Confirm both the native foundation library and custom canvas load.
2. With the Poke tool, focus Keyboard and type ASCII into TTY; test focus changes.
3. Set stock X/Y to origin and far corner, exercise every color, Plot and Clear.
4. Set custom Color nonzero, Plot=1 and Ack=1; press/drag/release in the canvas.
   Verify visible painting and correct final button state. Test release outside
   the canvas and changing focus while a button is held.
5. Set Ack=0; confirm a queued packet remains unchanged across ticks. Resume
   acknowledgement and verify order. Pause/resume simulation with pending input;
   exercise overflow and reset recovery. Document any dropped-release behavior.
6. Save a disposable copy, close/reopen it, and repeat text/pixel smoke checks.
   Do not replace generator-owned source with the simulator's rewritten copy.
7. Record responsiveness at a stated tick rate. Keep startup time separate from
   steady input-to-visible-response latency.

includes the prebuilt bridge and its source, and passes ZIP integrity checking.
Repeated bridge builds also retained the SHA-256 recorded above. These checks do
not establish the network-disabled desktop result above. No v0.0.1 release is
